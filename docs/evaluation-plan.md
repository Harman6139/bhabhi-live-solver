# Preregistered Evaluation Plan

- Protocol: `eval-v1`
- Preregistered: 2026-07-27, before solver implementation or result-driven tuning
- Strength-selection rules: canonical default profile only
- Variant results: correctness and robustness, not mixed into the primary metric
- Status: frozen except through the change-control section below

This file specifies decisions before results are observed. A generated protocol
manifest will hash this file, rule/config/model definitions, candidate list,
seed manifest, code state, and summarizer before qualification or final data are
opened.

## 1. Questions

1. Which eligible production configuration minimizes the user's complete-game
   probability of being the final player holding cards?
2. Do advanced belief, behavior, search, and endgame components improve terminal
   decisions without violating correctness, calibration, robustness, or live
   latency?
3. Are displayed probabilities calibrated and appropriately uncertain?
4. Does the shipped local UI remain responsive and reject obsolete analysis?

## 2. Splits and data access

Seed namespaces are disjoint:

- `dev`: debugging, profiling, pilot variance/runtime; never evidence.
- `train`: fit behavioral parameters only.
- `tune`: choose hyperparameters and provisional architecture.
- `qualification`: compare a frozen set of at most six full configurations and
  material ablations.
- `final`: one-shot comparison of the selected production candidate with the
  frozen hard-constraint reference.

`final` is not generated or read until the code/config/model hashes, candidates,
fallback order, cell definitions, sample size, environment policy, and report
script are frozen. A case never moves between splits.

The synthetic simulator owns hidden truth. Production inference and search
receive only the exact user hand and public event sequence. Evaluation truth is
stored in a separate eval-only sidecar and joined only by scorer code.

## 3. Seed and pairing policy

The base-deal seed is the first 128 bits of:

```text
SHA-256("bhabhi/eval-v1|<split>|deal|<baseIndex>")
```

It intentionally excludes opponent-style cell and configuration, so the same
base deal and its three rotations are crossed through every primary style cell
and candidate. Other 128-bit stream seeds use:

```text
SHA-256("bhabhi/eval-v1|<split>|<stream>|<cell>|<baseIndex>|<rotation>|<replicate>")
```

The implementation freezes the PRNG algorithm and version. A seed-manifest
checksum is stored with every run.

Independent deterministic substreams are derived by name:

```text
deal
p2-policy
p3-policy
chance
belief
search
rollout
bootstrap
```

Opponent and chance streams are keyed by actor plus semantic decision/event
ordinal, not by consumption order from one shared mutable generator. At a fixed
root, every candidate action reuses sampled worlds and rollout random numbers
where branch semantics permit.

Every configuration receives the same base deals, rotations, opponent policy
seeds, and genuine chance streams. Full-game trajectories can diverge, so
pairing after the initial scenario is not assumed.

## 4. Deals, rotations, and state corpora

For every style cell and base seed:

1. uniformly shuffle all 52 cards;
2. deal the full deck as 18/17/17;
3. run three cyclic rotations of the dealt hands among User, Player 2, and
   Player 3 while keeping role policies fixed.

The three rotations are one statistical cluster. This balances the 18-card hand
and A♠ ownership within every base deal. Reversed opponent styles are separate
cells because seat order is strategic.

No nontermination, invariant failure, or turn-cap event is silently removed.
Such a record remains in the denominator and is a simulator defect/release
blocker until explained.

A candidate-independent decision corpus is generated by frozen policies, never
from a configuration's own favored trajectory. Snapshot strata include:

- three-player early, middle, and late game;
- heads-up;
- 1, 2–3, and 4+ legal actions;
- user with/without power;
- no pickup versus visible-pickup history;
- known void, likely void, and no void evidence;
- small/exact versus large belief support.

The corpus also includes mandatory trap fixtures and exhaustive or reduced-deck
toy positions.

## 5. Opponent-style suite

Every simulator opponent sees only its hand and legitimate public information.
The equal-weight primary ordered cells are frozen as:

1. `random / random`
2. `always-high / always-high`
3. `always-low / always-low`
4. `shortest-suit / shortest-suit`
5. `early-high-shedder / early-high-shedder`
6. `power-avoider / power-avoider`
7. `documented-basic / documented-basic`
8. `always-high / always-low`
9. `always-low / always-high`
10. `shortest-suit / early-high-shedder`
11. `early-high-shedder / shortest-suit`
12. `power-avoider / documented-basic`
13. `documented-basic / power-avoider`
14. `random / documented-basic`
15. `documented-basic / random`
16. `noisy-mixture / phase-switch`
17. `phase-switch / noisy-mixture`

The exact policy feature weights, tie breaks, noise, and phase transition are
frozen in the protocol manifest. `noisy-mixture` and `phase-switch` are never
used to fit behavioral parameters. Learned/search agents form a secondary
stress suite. Perfect-information agents are test-only diagnostics and are
never eligible production evidence.

## 6. Configurations and baselines

Required reported policies:

- random legal;
- always high;
- always low;
- shortest-suit preference;
- early high-card shedder;
- power avoider;
- strongest documented basic heuristic;
- hard-constraint imperfect-information solver with behavioral inference off;
- every material advanced-component ablation;
- selected production configuration.

The confirmatory reference is the strongest frozen eligible hard-constraint
solver with behavioral inference disabled, not a trivial heuristic.

Before qualification, freeze no more than six full candidate configurations and
an ordered fallback list. Qualification chooses among these; final evaluates
only the selected candidate and frozen reference.

### Phase 7 development comparison freeze

The Phase 7 integration screen is a development-only protocol extension named
`phase7-paired-comparison-v1`. It cannot establish qualification eligibility,
enable a production component, or support a “beats” claim.

The two full-game configurations are frozen as:

| Configuration                            | Root decision method                                                                     | Hard belief | Behavior weighting | Continuation model                                                |
| ---------------------------------------- | ---------------------------------------------------------------------------------------- | ----------- | ------------------ | ----------------------------------------------------------------- |
| `phase5-balanced-hard-only-reference-v1` | Frozen Phase 5 Balanced terminal root rollout                                            | on          | off                | deterministic `documented-basic` for User, Player 2, and Player 3 |
| `phase7-exact-then-phase5-fallback-v1`   | Try exhaustive information-state endgame, otherwise the identical frozen Phase 5 request | on          | off                | deterministic `documented-basic` for User, Player 2, and Player 3 |

The simulator's 17 opponent-style cells remain external stress environments;
their identities are not disclosed to either solver. Both configurations
receive identical public timelines and configuration-independent deal,
opponent-policy, chance, belief, search, rollout, and bootstrap seeds. The exact
screening limits are frozen before the recorded run:

```text
maxActiveCards = 7
maxJointHypotheses = 196
maxInformationStates = 128
maxBranches = 512
deadlineMs = 1000
```

Run a complete-matrix smoke with one base deal first
(`2 configurations × 17 cells × 1 baseIndex × 3 rotations = 102 games`).
After code and schemas are frozen, record a development screen with four base
deals (`408 games`). Pair terminal outcomes only by `baseIndex`; never pair
divergent turns. Use 20,000 crossed cluster-bootstrap resamples.

The hardened artifact profile freezes `baseIndexStart = 0` and distinguishes
three noninterchangeable run kinds: `smoke` is exactly 102 games,
`development-primary` is exactly 408 games, and
`development-reproduction` is a fresh 408-game execution precommitted to the
primary artifact. Solver chance is a style-neutral stream distinct from the
private simulator chance stream; no deal, opponent-policy, environment-chance,
or style-derived seed crosses the solver boundary. Source content is captured
before and after every long run and publication is refused if it changes.

No individual run may claim rerun reproducibility. The rerun gate is established
only by a separate write-once attestation that independently replays and
verifies the smoke, primary, and reproduction artifacts; binds both development
manifests and checksum manifests; requires the same scientific contract and
frozen source; and compares the two timing/environment-free scientific digests
byte for byte. This schema-v2 hardening was frozen after a no-write diagnostic
smoke exposed artifact-validation defects and before any valid Phase 7 artifact
or paired result was produced; it changes no metric, threshold, candidate, seed
coordinate, or sample size.

The recorded development gate requires the complete matrix, identical scenario
coverage, zero simulation failures/caps/invariant errors/cancellations, at least
one selected Exact decision, typed retention of every exact refusal, zero
deadline refusals, no partial result labelled Exact, truth-firewall and frozen
fallback-parity tests, replay-valid raw games/truth sidecars, and a
byte-identical scientific digest on a fixed-seed rerun after excluding declared
timing/environment fields. Report the paired macro delta and interval without a
directional pass criterion. If the advanced configuration is not demonstrably
better or identical, Phase 7 retains the already eligible Phase 5 reference;
the advanced component remains off. Qualification noninferiority,
catastrophic-style, multiplicity, latency, and production-selection gates remain
Phase 8 work on clean seeds.

## 7. Primary metric and terminal selection

For complete game \(g\):

```text
Y_g = 1 if the user is the final player holding cards, otherwise 0
```

The primary metric is the equal-weight macro mean of the 17 cell-level user
Bhabhi rates under canonical rules at the shipped production budget (normally
Balanced). Lower is better.

For candidate \(C\) and reference \(R\):

```text
Delta = BhabhiRate(C) - BhabhiRate(R)
```

Report absolute percentage-point delta. Relative delta is descriptive only.

- Claim **beats** only if the untouched-final two-sided 95% paired interval for
  `Delta` lies wholly below zero.
- Terminal noninferiority margin is +0.5 percentage point: the one-sided 95%
  upper bound must be below `+0.005`.
- Treat an absolute point difference at or below 0.25 percentage point with an
  interval spanning zero as a practical tie.
- Tie breakers: better calibration/robustness, then lower Balanced p95 latency,
  then simpler configuration.
- Proxies such as hand count or pickup size never override terminal Bhabhi risk.

If final fails terminal noninferiority, ship the first preregistered eligible
fallback/reference and report the advanced result as inconclusive or harmful.

## 8. Secondary metrics

### Outcomes and diagnostics

- safe rate;
- first/second escape probabilities and finishing-position distribution;
- immediate pickup probability and expected pickup size;
- power probability;
- game length;
- results by style, seat/order, A♠ holder, and 18-card holder;
- worst cell, cell dispersion, four deterministic seed shards, and held-out
  style subset.

### Exact/toy decisions

- tie-aware best-action agreement;
- terminal-value regret;
- probability RMSE against exact values;
- brute-force agreement for exact endgame values.

### Belief, action, and terminal calibration

- Brier score;
- log loss;
- reliability curves with 10 fixed-width bins and bin counts;
- 50%, 80%, and 95% interval coverage;
- card-owner, current-void, suit-length, overtake, joint, and conditional query
  accuracy;
- discretionary action NLL/top-1 accuracy, with forced actions reported
  separately;
- displayed terminal-risk Brier score and log loss.

Brier and logarithmic scores are used as proper scoring rules, with reliability
kept conceptually separate from resolution:
[Brier 1950](<https://doi.org/10.1175/1520-0493(1950)078%3C0001:VOFEIT%3E2.0.CO;2>),
[Good 1952](https://doi.org/10.1111/j.2517-6161.1952.tb00104.x), and
[Gneiting & Raftery 2007](https://doi.org/10.1198/016214506000001437).

### Compute and stability

- worlds, nodes, iterations, horizon, entropy, ESS;
- wall-time p50/p95/p99, CPU time, and peak memory;
- cold start versus warm requests;
- cancellation count and obsolete publication count;
- four seed-shard estimates.

## 9. Statistical method and stopping

Primary differences use a crossed paired cluster bootstrap over base-deal IDs:
resampling one `baseIndex` retains its entire style-cell × rotation matrix for
every compared configuration. Per-cell reports use the same base-deal resample
restricted to that cell. Rotations and all observations within a game remain
inside their cluster. Use 20,000 resamples and the frozen `bootstrap` seed.

Calibration resamples whole synthetic games/trajectories. Latency resamples
source-state/game clusters. Turns, cards, and rotations are never treated as
independent observations.

On `dev` only, estimate paired per-cluster variance and runtime. Before opening
qualification, choose equal base-deal count per cell using the paired-macro
half-width formula:

- target two-sided 95% half-width: 1.0 percentage point;
- inflate computed count by 10%;
- round up to a block of 16;
- clamp to 64–512 base deals per cell;
- compute cap: 48 CPU-hours per configuration.

If the cap is reached, stop only after a complete block across every cell and
label the comparison underpowered/inconclusive. Never stop because an effect,
sign, interval, or p-value looks favorable.

Determine final sample count before opening final using qualification variance,
not effect sign, with the same half-width target, clamping, blocks, and fresh
seeds.

Calibration count is selected from `dev` variance for a Brier-difference
half-width target of 0.005, minimum 1,000 and maximum 10,000 synthetic game
clusters, with a 24 CPU-hour/configuration cap.

Latency uses at least 1,000 warm representative requests per live budget and at
least 100 cold starts. ECE is descriptive because binning is biased. Log-loss
numerics use epsilon `1e-12`; logically possible truth assigned zero support is
counted separately and can block release.

Qualification multiplicity uses Holm adjustment (or simultaneous bootstrap
intervals recorded in the manifest) over frozen candidate-versus-reference
comparisons.

## 10. Calibration protocol

Score deterministic checkpoints:

- initial and post-opening;
- fixed public-event ordinals;
- immediately before opponent choices;
- after thulla and visible pickup events.

Average queries within state, then states within game, so large hands/long games
do not dominate. Hard-known predictions are separated from unresolved soft
predictions.

Equal-weight query families:

- card owner;
- current void;
- exact or threshold suit length;
- can overtake;
- canonical joint event such as `P2 can overtake AND P3 is void`;
- conditional queries only when the conditioning denominator exceeds the
  frozen manifest floor.

Action prediction scores the observed action against the full legal alternative
set in each world. Forced and discretionary actions are separate. Required
robustness checks prove one noisy legal action retains support and cannot cause
near-certain model/world classification.

Behavior parameters are fit on train; probability floors, temperatures,
particle count, and component choices are made on tune; the serialized model is
hashed before qualification/final. There is no recalibration on final.

## 11. Required ablations

- behavior off/on;
- shared versus separate opponent models;
- likelihood tempering/error mixture on/off;
- constrained enumeration, direct sampling, and particles where eligible;
- resampling and rejuvenation on/off;
- world/particle count;
- search horizon/budget;
- weighted determinization versus information-set/belief search;
- robust model ensemble on/off;
- exact endgame on/off;
- rollout/strategy feature bundle leave-one-out;
- common-random-number variance and cost;
- strongest basic heuristic versus hard-only solver versus final.

Invalid designs—independent marginals as the world, observed-action-only
likelihood, truth-aware production rollouts, colluding opponents, or hand-count
utility—may appear only as negative diagnostics. They can never be eligible.

## 12. Component eligibility

Every production component/configuration must:

1. pass all correctness, invariant, conservation, replay, truth-firewall, and
   exact-agreement tests with zero known failure;
2. reproduce fixed-seed outputs;
3. meet live latency, cancellation, stale-publication, and memory gates;
4. have terminal noninferiority upper bound below +0.5 percentage point;
5. show no preregistered catastrophic style regression;
6. satisfy its evidence-specific rule:
   - a performance/search component must improve paired terminal risk on clean
     qualification after multiplicity control;
   - behavioral inference may instead improve a prespecified calibration,
     hidden-state, action-prediction, robustness, or downstream-decision metric
     while retaining terminal noninferiority;
   - correctness-required exact methods may qualify on exact agreement plus
     noninferiority.

Among eligible full configurations, select the lowest qualification macro
Bhabhi estimate and apply the practical tie rule. Disable an inconclusive
advanced component unless correctness requires it.

Catastrophic style regression is preregistered as a cell point regression of
5 percentage points or more whose one-sided 95% lower bound exceeds 2 percentage
points against the reference. This is a robustness disqualifier.

## 13. Live and offline budgets

Measured from a production build on the documented development machine:

| Mode                |      Compute deadline |         Visible/service objective |
| ------------------- | --------------------: | --------------------------------: |
| Deterministic event |                   n/a | feedback p95 ≤ 100 ms; report p99 |
| Instant             |  500 ms worker budget | valid recommendation p95 ≤ 750 ms |
| Balanced            |   2.5 s worker budget |  valid recommendation p95 ≤ 3.0 s |
| Deep                |    15 s worker budget |   valid recommendation p95 ≤ 20 s |
| Offline             | 60 s default per root |     configurable; always recorded |

Additional gates:

- analysis causes zero main-thread tasks longer than 50 ms;
- entry while analysis runs remains p95 ≤100 ms;
- obsolete results published: zero in at least 1,000 rapid-edit/cancel races;
- worker memory and peak process memory are reported, not inferred.

Initial latency machine:

- Windows 11 Home Single Language, build 26200, 64-bit;
- Intel Core i5-9300H, 4 cores / 8 logical processors;
- 8,225,972 KiB visible physical memory;
- Node.js v22.13.0, npm 10.9.2.

Every run additionally records power mode/AC state, free memory, browser and
user-agent version, worker count, build/code/config/model/protocol hashes,
clean/dirty status plus diff hash, warmup, background-load policy, timestamp,
timezone, screen size, and DPR. Hardware-based threshold changes require an ADR
before holdout and a clean rerun.

## 14. Immutable artifact contract

```text
artifacts/evaluation/eval-v1/<split>/<run-id>/
  manifest.json
  environment.json
  seeds.ndjson
  games.ndjson
  decisions.ndjson
  calibration-predictions.ndjson
  truth.eval-only.ndjson
  latency.ndjson
  failures.ndjson
  summary.json
  summary.md
  checksums.sha256
  command.txt
  logs/
```

Raw runs are never overwritten. Every record contains `schemaVersion`, run,
config/rule/style/split IDs, seed/base-deal/rotation/replicate, public state and
history hashes, state version, relevant RNG IDs, and completion/failure status.
Games include terminal identity/order, turns/counts, terminal hash, and timings.
Decisions include legal set, choice, per-action estimates/intervals,
method/budget/worlds/iterations/ESS, and cancellation.

Summaries derive solely from raw records. Verification must reproduce summary
bytes except fields explicitly declared nondeterministic in the manifest.

## 17. Threats to validity

Explicitly guard against:

- pseudoreplication of turns, cards, or rotations;
- mutable RNG consumption destroying pairing;
- tuning on final or outcome-dependent stopping;
- multiple-comparison winner's curse;
- model-matched simulator overfitting;
- candidate-generated snapshot bias;
- seat, A♠, or 18-card imbalance;
- silently excluded failures/nonterminations;
- hard-known cards dominating calibration;
- forced actions mixed with discretionary actions;
- ECE/binning and zero-support clipping artifacts;
- truth-sidecar import leakage;
- opponent policies receiving illegitimate information;
- treating divergent trajectories as paired turns;
- unstable relative deltas;
- p95 estimates from too few independent clusters;
- JIT/cache/thermal/background-load bias;
- labeling sampled search as exact.

## 18. Change control

After any tune/qualification/final result is viewed:

- never silently edit thresholds, cells, seed policy, or stopping;
- document the old rule, new rule, reason, and affected evidence in an ADR;
- behavior-affecting fixes after final unsealing invalidate that run and require
  a new protocol ID such as `eval-v2` with fresh seeds;
- pure reporting fixes may resummarize identical raw hashes and must record both
  summary hashes.
